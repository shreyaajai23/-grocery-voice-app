# Getting this app onto your iPhone

This machine (Windows) can't compile an iOS app — that always requires Xcode on
macOS, no matter what framework you use. We tried a free path via
**Codemagic** (a CI service with free macOS build machines) using your
existing free Apple ID, and confirmed it's a dead end:

- Codemagic's **Automatic** signing needs an App Store Connect API key, which
  requires enrolling in the paid Apple Developer Program ($99/yr) — a free
  Apple ID has no App Store Connect access at all.
- Codemagic's **Manual** signing needs a certificate + provisioning profile
  that, for a free/personal-team Apple ID, can *only* be generated by running
  Xcode's GUI on an actual Mac at least once. No CI service can generate this
  headlessly for a free account.

So the real options are:

1. **Pay for the Apple Developer Program ($99/yr)** — unlocks fully headless
   Codemagic builds via the API key, no Mac ever needed, no expiry. The repo
   (github.com/shreyaajai23/-grocery-voice-app) and Codemagic app are already
   connected and configured for the iOS build — the only missing piece is the
   App Store Connect API key under Distribution → iOS code signing →
   Automatic, generated at appstoreconnect.apple.com/access/api once you're
   enrolled.

2. **One-time Mac access** (borrow one, or rent by the hour — e.g. MacinCloud)
   to generate a free personal-team cert/profile in Xcode once, then upload
   those to Codemagic's Manual signing. Still expires every ~7 days, so
   you'd repeat this regularly — an ongoing hassle, not a one-time fix.

3. **Use Android instead** — the app already works today, no cost, no Mac,
   no CI. This is what we went with; the app runs identically on Android
   and the code is the same either way.

If you want to revisit iOS later, come back to this doc — the repo and
Codemagic project are already set up, so option 1 is just a matter of paying
Apple and plugging in the API key.
